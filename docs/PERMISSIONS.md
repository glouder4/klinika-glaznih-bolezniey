 # Система прав доступа

## Обзор

Модуль календаря использует гибкую систему прав доступа для управления действиями пользователей. Права могут назначаться как напрямую пользователям, так и через группы пользователей Bitrix.

## Структура прав

### Базовые права (для врачей/сотрудников)

| Код права | Название | Описание |
|-----------|----------|----------|
| `calendar.view` | Просмотр записей | Право на просмотр своих записей в календаре |
| `calendar.view_all` | Просмотр всех записей | Право на просмотр записей всех врачей |
| `calendar.create` | Создание записи | Право на создание новых записей в календаре |
| `calendar.edit_own` | Редактирование своих записей | Право на редактирование только своих записей (формат «Своим») |
| `calendar.edit_all` | Редактирование всех записей | Право на редактирование записей всех врачей (формат «Всем») |
| `calendar.edit_title_own` | Редактирование названия записи (своих) | Право на редактирование названия только своих записей (формат «Своим») |
| `calendar.edit_title_all` | Редактирование названия записи (всех) | Право на редактирование названия у любых записей (формат «Всем»: свои и чужие) |
| `calendar.edit_own_notes` | Редактирование заметок своих записей | Право на редактирование заметок в своих записях календаря |
| `calendar.edit_others_notes` | Редактирование заметок чужих записей | Право на редактирование заметок в чужих записях календаря |
| `calendar.move` | Перемещение записи | Право на перемещение записей в календаре |
| `calendar.confirm` | Подтверждение записи | Право на установку статуса подтверждения (Подтверждено/Не подтверждено). Не даёт право на отмену записи |
| `calendar.cancel` | Отмена записи | Право на отмену записи и возврат в расписание. Владелец может отменять свои записи без этого права |
| `calendar.delete_own` | Удаление своих записей | Право на удаление только своих записей |
| `calendar.delete_all` | Удаление всех записей | Право на удаление записей всех врачей |

### Административные права

| Код права | Название | Описание |
|-----------|----------|----------|
| `calendar.manage_groups` | Управление группами и правами | Право на создание групп пользователей и управление правами доступа |
| `calendar.manage_schedule` | Управление расписанием | Право на управление расписанием врачей (создание/редактирование расписаний) |
| `calendar.manage_branches` | Управление филиалами | Право на управление филиалами клиники |
| `calendar.manage_contact` | Создание и привязка контакта к записи | Право на создание нового контакта в CRM и привязку/изменение контакта в событии календаря |
| `calendar.manage_deal` | Создание и привязка сделки к записи | Право на создание сделки в CRM, привязку сделки к событию календаря и просмотр деталей сделки |
| `calendar.set_visit_status` | Установка статуса визита | Право на установку статуса визита в записи (Клиент пришел / Клиент не пришел / Не указано) |
| `calendar.change_employee` | Смена ответственного врача | Право на смену ответственного врача в записи |

## Логика работы прав

### Просмотр записей

- Пользователь с правом `calendar.view` видит только свои записи
- Пользователь с правом `calendar.view_all` видит все записи всех врачей и получает **переключатель** в тулбаре: «Все записи» / «Мои записи» / выбор конкретного врача
- Администраторы (`$USER->IsAdmin()`) видят все записи и переключатель

### Редактирование записей

- Пользователь с правом `calendar.edit_own` может редактировать только свои записи
- Пользователь с правом `calendar.edit_all` может редактировать любые записи
- Для полного доступа к редактированию рекомендуется назначить оба права

### Редактирование названия записи (форматы «Своим» / «Всем»)

В интерфейсе прав используются два формата охвата записей:
- **Своим** — только свои записи
- **Всем** — все записи (включая свои); «Всем» подразумевает и «Своим»

- `calendar.edit_title_own` — право на редактирование названия **только своих** записей (формат «Своим»).
- `calendar.edit_title_all` — право на редактирование названия **у любых** записей (формат «Всем»: свои и чужие). Без права название нельзя менять ни у одной записи.

### Подтверждение и отмена записей

- `calendar.confirm` — право на **подтверждение** (выпадающий список «Подтверждено» / «Не подтверждено»). Не даёт право на отмену.
- `calendar.cancel` — право на **отмену** и возврат в расписание (кнопка «Отменить запись» / «Вернуть в расписание»). Владелец записи может отменять свои записи без этого права.

### Редактирование и удаление (только granular-права)

- **Редактирование:** используются только `calendar.edit_own` и `calendar.edit_all`. Право `calendar.edit` удалено.
- **Редактирование названия:** используются только `calendar.edit_title_own` и `calendar.edit_title_all`. Право `calendar.edit_title` удалено.
- **Удаление:** используются только `calendar.delete_own` и `calendar.delete_all`. Право `calendar.delete` удалено.

### Удаление записей

- Пользователь с правом `calendar.delete_own` может удалять только свои записи
- Пользователь с правом `calendar.delete_all` может удалять любые записи
- **Внимание:** Удаление записей также удаляет историю в журнале

### Редактирование заметок к записям

- `calendar.edit_own_notes` — право на **редактирование заметок в своих записях**. Без этого права владелец записи не может добавлять и редактировать заметки в своих событиях.
- `calendar.edit_others_notes` — право на **редактирование заметок в чужих записях**. Без этого права пользователь не может редактировать заметки в событиях других врачей.

### Создание и привязка контакта к записи

- `calendar.manage_contact` — право на **создание нового контакта в CRM** и **привязку/изменение контакта** в событии календаря. Без этого права кнопка «Добавить» клиента в карточке события скрыта, а AJAX-вызовы `createContact` и `saveEventContact` возвращают ошибку доступа.

### Создание и привязка сделки к записи

- `calendar.manage_deal` — право на **создание сделки в CRM**, **привязку сделки** к событию календаря и **просмотр деталей сделки**. Без этого права карточка «Сделка» (кнопки createNewDeal, openDealDetails, Выбрать) скрыта, а AJAX-вызовы `createDealForEvent`, `saveEventDeal`, `saveDealCustomFields` возвращают ошибку доступа.

### calendar.manage_employees

Право `calendar.manage_employees` **не используется** в модуле календаря. Если оно есть в настройках групп — его можно удалить. Управление сотрудниками (врачами) в календаре реализовано через `calendar.manage_schedule` (расписание) и `calendar.change_employee` (смена ответственного в записи).

## Рекомендуемые наборы прав

### Врач (базовый доступ)
- `calendar.view` - просмотр своих записей
- `calendar.create` - создание записей
- `calendar.edit_own` - редактирование своих записей
- `calendar.edit_own_notes` - редактирование заметок своих записей
- `calendar.delete_own` - удаление своих записей
- `calendar.manage_contact` - создание и привязка контакта к записи

### Старший врач / Администратор клиники
- `calendar.view` - просмотр записей
- `calendar.view_all` - просмотр всех записей
- `calendar.create` - создание записей
- `calendar.edit_own` - редактирование своих записей
- `calendar.edit_all` - редактирование всех записей
- `calendar.move` - перемещение записей
- `calendar.confirm` - подтверждение записей (статус Подтверждено/Не подтверждено)
- `calendar.cancel` - отмена и возврат записей в расписание
- `calendar.manage_schedule` - управление расписанием
- `calendar.manage_contact` - создание и привязка контакта к записи

### Полный доступ (супер-админ)
Все права + группа "Артмакс.Календарь | Администраторы"

## Рут-пользователь

Пользователи с флагом `$USER->IsAdmin()` (администраторы Bitrix) имеют полный доступ ко всем функциям календаря без проверки прав. Это включает:
- Удаление любых записей
- Управление всеми настройками
- Доступ к административным функциям

## API для работы с правами

### Проверка права у пользователя

```php
use Artmax\Calendar\Permissions;

$permissions = new Permissions();
$hasPermission = $permissions->hasPermission($userId, 'calendar.edit_all');
```

### Получение всех прав пользователя

```php
$permissions = new Permissions();
$userPermissions = $permissions->getUserPermissions($userId);
// Возвращает массив прав пользователя
```

### Назначение прав группе

```php
$permissions = new Permissions();
$permissions->assignPermissionsToGroup($groupId, [1, 2, 3]); // ID прав
```

### Связывание группы календаря с группой Bitrix

```php
$permissions = new Permissions();
$permissions->linkBitrixGroup($calendarGroupId, $bitrixGroupId);
```
